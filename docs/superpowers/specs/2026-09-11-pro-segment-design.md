# Про-сегмент: лента без любительских лиг и точность по сегментам — дизайн

Дата: 2026-09-11. Статус: согласован по секциям, ждёт вычитки.
Затрагивает оба репозитория; источник истины — этот документ, план фронтенда ссылается на него.

## Зачем

Продукт обещает прогнозы Tier 1 (§1 спеки), а прод показывает и измеряет любительские игры.
Замерено на проде 11.09.2026:

- Все **249** сверенных прогнозов, у которых есть OpenDota-разбор, сделаны в **27 лигах с
  `league.tier = excluded`** у Valve (AD2L, FACEIT, миксер-кап турниры, инхаусы). Ни одной
  `professional` или `premium`.
- Из 18 предсказанных матчей, лежащих внутри диапазона `/proMatches`, в ленте сводок был **1**.
  Эти игры туда не придут никогда — дело не в отставании ленты.
- За всё время работы поллера в live прошло **305 карт в 32 лигах без разметки и 1 карта
  Tier 3**; Tier 1 и Tier 2 — ни одной. Разметка при этом есть: 31 лига Tier 1, 9 Tier 2, 26 Tier 3.

Последствия:

1. Дашборд точности (`app/api/accuracy.py`) не фильтрует по лигам — его цифры на проде на 100%
   про домен, которого модель не видела (обучение — только `/proMatches`).
2. Алерт дрейфа (`app/ml/drift.py`) читает те же прогнозы и через неделю начнёт реагировать на
   состав лиг в ленте, а не на деградацию модели.
3. Лента (`GET /api/matches/live`) и раздел «Сыграно» (`GET /api/matches/recent`) показывают
   «Downfall of angelos» под продуктом, называющимся прогнозом Tier 1.

Лента была оставлена без фильтра сознательно (коммит `c19e890`, 10.09.2026: «35 live-игр в 25
лигах, все без тира»), но из этого решения по умолчанию выросло и смешанное измерение — его никто
не выбирал.

## Решения, принятые при согласовании

| Вопрос | Решение | Почему |
|---|---|---|
| Учить на чём | **На всём про-сегменте, как сейчас** | §5.4: Tier 1 мало, обучение на всём корпусе + калибровка на Tier 1. Не меняется. |
| Мерить на чём | **По сегментам: Tier 1 / Pro / Excluded** | Оценка на целевом домене; Excluded — контрольная группа: если модель на любительских играх ведёт себя принципиально иначе, это сигнал о том, чего не хватает признакам. |
| Лента | **Отфильтровать**: сервер отдаёт только про-лиги, поверх — существующие чипы Liquipedia с Tier 1 по умолчанию | Пустая лента в 4 утра — честное состояние. Показывать любительские игры под обещанием Tier 1 — нет. |
| Признак «про» | **Тир Valve из `/leagues`**: `professional` / `premium` | Есть у новой лиги сразу; разметка Liquipedia для новой лиги появляется только после ручного `map-leagues` (`sync_liquipedia` на кроне — заглушка, `app/ingestion/workers/sync.py:14-21`). |
| Дашборд по умолчанию | **Tier 1** | Главная цифра страницы — про целевой домен, даже когда она пуста. |
| Пустая лента | **Разбор последнего завершённого матча + карточки «Сыграно»** | Интереснее ленты любительских игр и не отравляет измерения. |
| Резолвер | **Без изменений** — тянет исходы всех прогнозов | Исход дешёвый; контрольной группе он нужен. |
| Прогнозы по excluded | **Продолжают делаться и записываться** | Без них нет контрольной группы; фильтр живёт в выдаче, а не в поллере. |

## Замер: тир Valve против разметки Liquipedia

`/leagues` OpenDota (11.09.2026): 10 183 лиги — `excluded` 7320, `professional` 2485, `premium` 214,
`amateur` 59, пусто 105. Сверка с локальной базой:

| Liquipedia | Valve `premium` | Valve `professional` | Valve `excluded` |
|---|---|---|---|
| tier1 | 2 | 30 | 0 |
| tier2 | 0 | 6 | 1 |
| tier3 | 0 | 11 | 11 |

- **`premium` — практически только The International** (из лиг с матчами в базе: TI 2025, TI 2026
  и ещё одна). DreamLeague, BLAST Slam, ESL One, PGL Wallachia, EWC — `professional`, наравне с
  Tier 3. Valve не отличает Tier 1 от Tier 3, поэтому тир Valve — фильтр «про / не про», а Tier 1
  выделяет Liquipedia.
- **Тир Valve — текущий, а не исторический.** 23 400 из 68 704 сводок `/proMatches` в архиве (34%)
  принадлежат лигам, которые **сейчас** `excluded` (Destiny League, Dota 2 Space League, Ultras Dota
  Pro League, European Pro League): Valve переводит лиги в `excluded` со временем. У лиг, активных с
  июля 2026, на `excluded` приходится 93 карты из 2186. Для фильтра live-ленты текущий тир годится;
  приписывать его историческим данным задним числом — нет. Отсюда запись тира на прогноз в момент
  выдачи (раздел 1).

## 1. Откуда берётся сегмент

### Схема

Одна миграция, только схема — данных она не трогает (см. «Заполнение старых строк»).

| Таблица | Колонка | Тип | Примечание |
|---|---|---|---|
| `leagues` | `valve_tier` | `String(16)`, nullable | `premium` / `professional` / `amateur` / `excluded`; NULL — лиги нет в `/leagues` или её ещё не спрашивали |
| `predictions` | `league_id` | `BigInteger`, nullable, без FK | лига на момент прогноза — поллер её знает |
| `predictions` | `valve_tier` | `String(16)`, nullable | копия `leagues.valve_tier` на момент прогноза; после записи не переписывается |

`predictions.league_id` нужен, потому что сегмент Tier 1 иначе пришлось бы выводить через
`matches.league_id`, а у несверенного матча строки в `matches` может не быть вовсе: скелет
создаётся только из детального payload (инвариант 13). FK нет по той же причине, по которой его
нет у `predictions.match_id`: лог прогнозов пишется раньше, чем нормализованный слой узнаёт о
матче, и не должен от него зависеть.

### Правило сегмента

Одна функция `segment_of(valve_tier, liquipedia_tier) -> "tier1" | "pro" | "excluded" | None`
в `app/domain/segments.py`, рядом — `display_tier(valve_tier, liquipedia_tier)` (у всех функций правила тир Valve —
первый аргумент: оба `str | None`, и перестановку типы не поймают):

| `valve_tier` | `liquipedia_tier` | сегмент |
|---|---|---|
| `professional` / `premium` | `tier1` | `tier1` |
| `premium` | `unknown` / NULL | `tier1` — запасной путь §3 спеки |
| `professional` / `premium` | прочее | `pro` |
| `excluded` / `amateur` | любой | `excluded` — фильтр Valve первичен |
| NULL | любой | `None` |

- Тир Liquipedia берётся **джойном** к `leagues.tier` по `predictions.league_id`: разметка,
  сделанная позже, — более точное знание о той же лиге. Тир Valve — **с прогноза**: его смена — это
  смена статуса лиги, а не уточнение.
- `display_tier` возвращает `tier1`, если Liquipedia лигу не знает, а Valve говорит `premium`;
  иначе — тир Liquipedia. Это то, что видит пользователь в поле `tier` ленты и «Сыграно»: иначе
  следующий TI до ручной разметки прятался бы под чипом «Без разметки».
- В SQL правило повторено выражением `segment_expr()` (для дашборда и дрейфа). **Тест сверяет
  SQL-выражение с Python-функцией на всех комбинациях таблицы** — два места одного правила обязаны
  не разойтись молча.
- Строка «tier1 + excluded» по замеру не встречается (0 лиг), но правило её определяет: фильтр
  Valve первичен.

### Обновление тира Valve

- `parse_leagues` (`app/ingestion/reference.py:132`) начинает брать `tier` → `valve_tier`.
  `leagues.tier` (разметка Liquipedia) по-прежнему не трогается; докстринг, объясняющий, почему тир
  выбрасывается, переписывается — выбрасывался он, чтобы не затереть разметку, а отдельная колонка
  этот риск снимает.
- Новая arq-джоба `refresh_valve_tiers`: cron в **:03** и постановка в очередь из поллера.
  - Защита от частых вызовов: в начале джобы `SET valve_tiers:throttle NX EX 900`; ключ уже есть —
    джоба пишет `valve_tiers.skipped` и выходит. Не чаще раза в 15 минут, откуда бы её ни позвали.
  - `RateLimitedError` — останов, как везде. Иная ошибка — `log.warning`, старые значения остаются.
- Поллер: если у какой-то из live-лиг `valve_tier` NULL — `enqueue_job("refresh_valve_tiers",
  _job_id="refresh_valve_tiers")`. Сам поллер `/leagues` не вызывает: мегабайт в 30-секундном тике
  задерживал бы прогнозы. Лига, которой нет в `/leagues` вовсе, будет ставить джобу каждый тик, но
  защита ограничивает это четырьмя вызовами в час.
- CLI отдельной команды не получает: `reference` уже вызывает `refresh_league_names` и после правки
  сохраняет тир. Ручной запуск мимо защиты допустим — это человеческое событие.

### Заполнение старых строк

Новая идемпотентная команда `backfill-segments`:

- `predictions.league_id` — из `raw_live_snapshots.payload->>'league_id'` по `match_id`, где NULL;
- `predictions.valve_tier` — из текущего `leagues.valve_tier` по `league_id`, где NULL.

Второе — не point-in-time, и это оговорено в выводе команды и в докстринге. На проде таких строк
около 270 за последние дни; за такое окно текущий тир совпадает с тиром на момент прогноза. Новые
прогнозы с NULL-тиром (лига ещё не пришла из `/leagues`) команда тоже заполнит, если её запустить
снова; расписания у неё нет — это ручной инструмент выката.

Миграция не может сделать это сама: до первого вызова `/leagues` колонка `leagues.valve_tier`
пуста.

## 2. API, лента, дашборд, дрейф

### Поллер

- `_league_context` (`app/ingestion/workers/live_poller.py:81`) дополнительно читает `valve_tier`.
- `Prediction` получает `league_id` и `valve_tier`.
- Запись ленты (`LiveMatch`, `app/schemas/common.py:45`) получает `valve_tier: str | None`;
  `tier` считается через `display_tier`.
- `live:feed` в Redis по-прежнему содержит **все** игры: фильтр — в API. Одно правило для ленты и
  «Сыграно», а полная лента остаётся для отладки.
- Порядок ленты (`sort_feed` по `team_history`) не меняется.

### `GET /api/matches/live?tier=`

Отдаёт только записи, у которых `segment_of(valve_tier, …)` — `tier1` или `pro`. Существующий
параметр `tier` применяется после (он сравнивает `entry.tier`, то есть `display_tier`).

### `GET /api/matches/recent?limit=&tiers=`

- Матч попадает в выдачу, только если у него есть прогноз с `valve_tier` в `professional` /
  `premium`. Внутри матча все прогнозы из одной лиги, так что значения совпадают.
- Лига матча — `coalesce(matches.league_id, predictions.league_id)`.
- `tiers` — необязательный список через запятую из `tier1,tier2,tier3,unknown`, сравнивается с
  `display_tier`. Фильтр **на сервере**: при чипе Tier 1 последние 20 матчей могут не содержать ни
  одного Tier 1, хотя более ранние есть. Неизвестное значение — `422`.
- Остальной ответ `RecentMatch` без изменений; `tier` считается через `display_tier`.

### `GET /api/model/metrics?version=&segment=`

- `segment: Literal["tier1", "pro", "excluded"] = "tier1"`.
- Сегмент каждой строки — `segment_expr()` над `predictions.valve_tier` и
  `leagues.tier` (LEFT JOIN по `predictions.league_id`).
- **Все числа ответа считаются внутри сегмента**: `sample_size`, `matches`, `log_loss`, `brier`,
  `ece`, `by_minute`, `reliability`, а также `predicted_matches`, `awaiting_outcome`,
  `first_prediction_at`, `last_prediction_at` (`serving_progress`).
- Новые поля `ModelMetrics`:
  - `segment: str` — какой сегмент посчитан;
  - `segments: list[SegmentCount{segment, matches}]` — сверенные матчи версии по каждому из трёх
    сегментов, всегда все три, включая нули;
  - `unsegmented_matches: int` — сверенные матчи версии с сегментом `None`.
- `versions` остаётся общим (без сегмента) — это список того, что вообще отдавалось.
- `training` (карточка модели) не меняется.

### Дрейф

- `check_calibration_drift` (`app/workers/drift.py:24`) проходит по парам (версия × сегмент) для
  `tier1`, `pro`, `excluded`; `load_scored` получает параметр `segment`.
- Окна (7 дней), порог шума `0.077·√(85/n)`, `MIN_MATCHES = 40` — **на сегмент**, без изменений.
- В строки `calibration.drift` / `calibration.checked` добавляется `segment`.
- Хранилища и API у дрейфа по-прежнему нет. В Tier 1 почти всегда будет `not enough data` — это
  честно: 40 сверенных карт Tier 1 за неделю бывают только во время крупного турнира.

### Ошибки

| Ситуация | Поведение |
|---|---|
| `/leagues` не ответил | `log.warning`, старые значения остаются; лига без тира скрыта из ленты |
| 429 от OpenDota | `RateLimitedError` → джоба останавливается; защита не даёт повторить раньше 15 минут |
| Лиги нет в `/leagues` | `valve_tier` NULL → в ленте нет, на дашборде — в `unsegmented_matches` |
| `segment` / `tiers` с неизвестным значением | `422` |

## 3. Фронтенд

### Главная (`src/routes/live.tsx`)

- **Чипы тиров** (`TierFilter`, `src/lib/tiers.ts`) остаются как есть; они работают поверх уже
  отфильтрованной сервером ленты. «Без разметки» теперь означает «про-лига без разметки
  Liquipedia»; подсказка «идут N матчей в турнирах других уровней» считает только про-матчи — сама
  собой, потому что сервер больше не отдаёт остальные. Подпись чипа не меняется.
- `recentMatchesQuery(limit, tiers)` передаёт выбранные чипы; ключ запроса включает `tiers`.
- **Есть live-матчи выбранного тира** — раскладка как сейчас; «Сыграно» показывает все матчи из
  `recent`.
- **Нет live-матчей выбранного тира**:
  1. строка пустого состояния — текст и подсказка как сейчас;
  2. **`LastMatchReview`** (новый компонент, `src/components/LastMatchReview.tsx`): первый матч из
     `recent`, догружает `matchDetailQuery(id)`; шапка — лига, команды, результат, дата; существующий
     `ProbabilityChart` с событиями таймлайна и отметкой перелома; подпись по `decidedMinute`;
     ссылка на страницу матча;
  3. «Сыграно» — карточки `recent` **без первого матча**.
- `recent` пуст — строка пустого состояния и прежнее пустое «Сыграно», без `LastMatchReview`.
  На проде так будет до первого дня про-турниров: кривую завершённого матча дать нельзя, если
  поллер не видел его в live (снапшоты строятся из STRATZ, а STRATZ прод не пускает).

### `decidedMinute(curve, radiantWin)` — `src/lib/decided.ts`

Кривая сортируется по минуте; оценка победителя `p_w = radiantWin ? p_radiant : 1 − p_radiant`;
значение ровно 0.5 считается «≥ 0.5».

| Условие | Результат | Подпись | Отметка на графике |
|---|---|---|---|
| кривая пуста | `{ kind: "none" }` | — | нет |
| `p_w` последней точки < 0.5 | `{ kind: "never" }` | «Модель до конца не видела победителя» | нет |
| `p_w ≥ 0.5` во всех точках | `{ kind: "wire" }` | «Фаворит с первой минуты» | нет |
| иначе | `{ kind: "decided", minute }` — минута точки после последней, где `p_w < 0.5` | «Решён с N-й минуты» | вертикальная линия |

«never» возможен законно: последний live-снапшот снимается примерно за полминуты до падения трона.

`ProbabilityChart` получает необязательный проп `marker?: number` — минуту, у которой рисуется
`ReferenceLine`.

### Дашборд (`src/routes/accuracy.tsx`)

- Рядом с выбором версии — пилюли **Tier 1 · Pro · Excluded** с числом сверенных матчей из
  `segments`. По умолчанию Tier 1; выбор — состояние страницы. `modelMetricsQuery(version, segment)`,
  ключ запроса включает сегмент.
- У Excluded подпись: «контрольная группа — лиги вне домена обучения».
- Сегмент пуст (`sample_size === 0`): «В Tier 1 сверенных матчей пока нет» и счётчики остальных
  сегментов; при `unsegmented_matches > 0` — «ещё N без известного тира».
- `ModelStrip` на главной сегмент не передаёт и получает серверный Tier 1.

### Типы (`src/api/types.ts`)

- `LiveMatch.valve_tier: string | null`
- `ModelMetrics.segment: string`, `ModelMetrics.segments: SegmentCount[]`,
  `ModelMetrics.unsegmented_matches: number`; `SegmentCount { segment: string; matches: number }`

### Телефон

`LastMatchReview` — во всю ширину, график высотой ~200 px; пилюли сегментов переносятся строкой.

## 4. Выкатка, тесты, документация

### Тесты бэкенда

- `segment_of` и `display_tier` — таблица всех комбинаций раздела 1.
- `segment_expr()` против `segment_of` на всех комбинациях — тест с БД.
- `parse_leagues` кладёт `valve_tier`; `refresh_league_names` не трогает `leagues.tier`
  (расширение `TestLeagueNames`, `tests/test_enrich_live.py`).
- `refresh_valve_tiers`: второй запуск в пределах 15 минут — `skipped`; 429 — останов.
- Поллер: прогноз получает `league_id` и `valve_tier`; лига без тира — ровно одна постановка с
  `_job_id`; запись ленты несёт `valve_tier`; `tier` учитывает `premium → tier1`.
- `/api/matches/live`: `excluded` и NULL скрыты, `pro` и `tier1` видны, `?tier=` работает поверх.
- `/api/matches/recent`: матч с прогнозами только в excluded-лиге не отдаётся; `tiers` фильтрует;
  неизвестное значение — `422`.
- `/api/model/metrics`: числа считаются внутри сегмента; `segments` — всегда три ключа;
  `unsegmented_matches`; по умолчанию `tier1`; неизвестный `segment` — `422`.
- Дрейф: вердикт на (версия × сегмент), `segment` в строке лога.
- `backfill-segments`: заполняет только NULL, повторный прогон ничего не меняет.
- Миграция: `alembic upgrade head` на тестовой схеме; откат на пустой базе гоняет CI.
- Перед пушем — как CI и без `.env`:
  `docker compose run --rm -e STRATZ_API_TOKEN= -e STEAM_API_KEY= tools python -m pytest`,
  плюс `ruff check . && ruff format --check . && mypy app`.

### Тесты фронтенда

- `decidedMinute`: четыре исхода таблицы, одна точка, точка ровно 0.5, неотсортированная кривая.
- `live.test.tsx`: пустая лента → `LastMatchReview` из заглушек `recent` и `/api/matches/{id}`;
  `recent` запрашивается с `tiers`; первый матч не дублируется в «Сыграно».
- `accuracy.test.tsx` (новый — у страницы тестов не было): пилюли сегментов с числами, текст пустого
  сегмента, строка `unsegmented_matches`.
- `npm run lint && npm run typecheck && npm test && npm run build`.

### Порядок работ и выкатка

1. Ветки `feature/pro-segment` в обоих репозиториях от `development`; мердж — туда же. Бэкенд
   первым: его изменения аддитивны (новые поля и необязательные параметры). Единственное видимое
   изменение для старого SPA — `/metrics` по умолчанию считает Tier 1; на тестовом сервере это
   допустимо до мерджа фронтенда.
2. В `main` — **только по явному разрешению владельца на этот выкат**, обоими образами сразу:
   `./deploy.sh <api-sha> <spa-sha>`.
3. Сразу после выката на проде — иначе до :03 все лиги считаются неизвестными и лента пуста:

   ```bash
   docker compose -f docker-compose.prod.yml run --rm api python -m app.ingestion.cli reference
   docker compose -f docker-compose.prod.yml run --rm api python -m app.ingestion.cli backfill-segments
   ```

4. Проверка: `GET /api/matches/live` не содержит excluded-лиг; `GET /api/model/metrics?segment=excluded`
   показывает ~250 сверенных матчей; `segments` для Tier 1 — 0.
